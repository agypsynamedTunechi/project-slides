Edo State's public data is hard to use

  • The numbers exist, but they are scattered across PDF year books, government portals and third party sites.
  • Most of them are static tables, so comparing one LGA with another means doing the work by hand.
  • Updates are infrequent, so published data goes stale (Ezema, 2023).
  • No maintained, LGA level dashboard existed for Edo State's 18 local governments.

Aim and objectives

To design and implement a web based system that presents key public indicators for Edo State's 18 local governments in an accessible, interactive form.

  • Source real, public data at LGA level
  • Design a relational database to hold it
  • Build an API that serves the data
  • Build an interactive dashboard for the public
  • Build an admin panel so the data can be kept current

What the literature says, and the gap

  • Open data only helps when it is presented in a form people can read (Graves and Hendler, 2014).
  • Even mature portals often publish summaries rather than genuinely open data (Wang and Shepherd, 2020).
  • Nigerian open data is patchy and infrequently updated (Ezema, 2023).
  • Civic tech groups such as BudgIT mostly work at national and state level (Zisengwe, 2024).

The gap

A maintained, LGA level dashboard for Edo State that covers several indicator categories and has a way to keep its data current.

How the system is built

  • Three tiers: the browser, an Express API, and a relational database.
  • One Express server serves both the pages and the API, so admin login sessions work reliably.
  • MySQL for local development, PostgreSQL when hosted.

The dashboard

  • Four category tabs: Economy, Demographics, Education and Health.
  • Pick any LGA to highlight it and see all of its figures.
  • Summary cards recalculate for each category.
  • If the server is down, it falls back to saved data and says so.

The admin panel

  • Password protected login, with passwords stored as bcrypt hashes.
  • Upload a CSV for any category.
  • Re-importing updates existing records and never duplicates them.
  • A bad row is rejected on its own, and the rest still import.
  • Every import is logged with the file, the count and the administrator.

Testing, and problems solved

Tested and passing

  • API endpoints, including a 404 for an unknown LGA.
  • Import blocked without login (401).
  • CSV upsert and per row error handling.
  • Dashboard with the backend on and off.
  • Category tabs and LGA selection.

Problems solved

  • Login failed across localhost and 127.0.0.1, so one server now serves everything.
  • A CDN failure broke the chart, so Chart.js is bundled locally.
  • Gaps and inconsistencies in the source data are documented, not guessed.
